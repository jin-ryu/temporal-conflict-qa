## P0. 실험 설계 결함 (실험 전 필수)

### P0-1. 검정력 분석 표 + 파일럿 수치 삽입 (W1, Q1)

**무엇을:** §3.1.1 재집계 블록 뒤 또는 §5 검정력 항목에 "지표별 예상 유효 분모" 표를 신설한다.

| 지표 | 조건 | 분모 산식 | 예상 N (가정: 탐지 70%, 해소 60%, 기권 5%) |
| :--- | :--- | :--- | :--- |
| AIR | L1=det ∧ L2=corr ∧ 비기권 | 67 × 0.7 × 0.6 × 0.95 | ~27/모델·환경 |
| LGR | baseline 오답 → 완화 후 정답 | (실측 의존) | 한 자릿수~10여 건 가능성 명시 |
| … | … | … | … |

**어떻게:**
1. 탐지율·해소율 가정값은 기존 파일럿(HoH×Gemini 게이트: 맹점 29% 실재)과 예비 실측으로 치환한다. 파일럿 수치가 있는 지표는 가정 대신 실측 기입.
2. 표와 함께 "N < 20인 셀은 점추정만 제시하고 비교 주장은 하지 않는다"는 사전등록 규칙을 명시한다 — 언더파워 셀에서 주장을 세우지 않겠다는 방어선.
3. 파일럿 결과(게이트 통과 근거)를 계획서에 1~2문장으로 삽입해 "현상이 실재한다"는 실행 가능성 근거로 쓴다 (Q1 대응).

**완료 기준:** 리뷰어가 "이 셀의 N이 얼마냐"를 물을 필요가 없는 상태.

### P0-2. 치환 기반 표본 확대 (W1 핵심 처방)

**무엇을:** DRAGged 비충돌 161건 중 사실형 문항에 Longpre(2021)식 치환을 적용해 **매칭된 사실 충돌 변형**을 파생하는 증강 트랙을 §3.1.1 전처리에 신설한다.

**설계 골자:**
1. 비충돌 161건에서 정답이 날짜·수치·개체인 사실형 문항을 선별 (예상 수율 50~70%).
2. 문항당 문서 10개 중 일부(예: 2~3개)의 정답 개체를 그럴듯한 오답으로 치환 → 오정보형 충돌 변형. 날짜 메타데이터를 조작해 구버전 문서를 만들면 시간형 충돌 변형도 가능 (시간 충돌 62건 한정 문제도 동시 완화).
3. 원본(비충돌)–변형(충돌) 쌍이 **within-item 매칭 대조**를 이루므로, RQ3의 DRAGged 내부 between-item 회귀 보정 의존도 크게 줄어든다 — W1과 §5 대조군 매칭 한계를 동시에 해소.
4. 자연 발생 67건은 "생태적 앵커"로 유지하고, 증강본은 "통제·검정력 트랙"으로 역할 분리해 서술한다. 주요 관측은 자연 67건에서 방향 확인 + 증강 트랙에서 유의성 확보의 2단 구조.

**주의:** 치환 문서의 자연스러움 검수(어색한 치환은 탐지 난이도를 인위적으로 낮춤) 절차를 함께 설계. 치환 위치·개수를 통제 변수로 기록.

**완료 기준:** 계획서에 증강 프로토콜 + 예상 표본 규모 + 자연/증강 트랙의 역할 분담 서술이 들어간 상태.

### P0-3. L2 라벨 규약 강화 (W2)

**무엇을:** §3.2.1 라벨 신뢰도 블록과 부록 A(b)를 수정.

1. **결론 확정 규칙 사전등록:** "트레이스 내 복수 결론·번복 시 **마지막 명시적 문서 지지**를 L2 결론으로 확정한다. 명시적 지지 없이 기울기만 있으면 unresolved(+암묵 leaning 부가 라벨)"를 §3.2.1에 명문화. 번복 횟수 자체도 부가 신호로 기록(부록 B 연계).
2. **인간 검증 재설계:** 무작위 200건 → **AIR·Discordant Hit 양성 전수 검증 + 나머지 셀 층화 표본**. 근거: 주장이 걸린 셀은 작아서 전수가 가능하다.
3. **κ 임계 상향:** 0.6 → **0.7**, 미달 시 라벨 정의를 수정하고 재라벨링하는 루프를 명시.

**완료 기준:** "이 트레이스의 L2 라벨은 무엇인가"를 두 사람이 독립적으로 같은 규칙으로 판정할 수 있는 상태.

### P0-4. Truncation 대조군 추가 (W4)

**무엇을:** §3.3.4 개입 표에 두 행 추가.

| 추가 대조 | 내용 | 목적 |
| :--- | :--- | :--- |
| **Filler-token 대조** | 절단 구간을 같은 길이의 무의미 토큰으로 대체 (Lanham 2023) | 정확도 하락이 "내용 제거" 때문인지 "길이/형식 붕괴" 때문인지 분리 |
| **자연 종료점 절단 (no-op)** | `</think>` 자연 종료 지점에서 절단 = 사실상 무개입 | 절단 절차 자체의 교란 크기 측정 (기준선) |

ΔAccuracy 해석 규칙도 명시: "인과 기여 = 절단 효과 − no-op 효과, filler 대조로 형식 교란 상한 확인."

**완료 기준:** Lanham을 인용하면서 그 대조 장치를 안 썼다는 지적이 성립하지 않는 상태.

## P1. 논문 방어력

### P1-1. 기권의 명시 상태 승격 (W5)

- §3.3.2 흐름 분석: before→after 흐름 행렬의 상태 공간에 `abstain`을 명시적으로 포함. "정상 경로 → 기권" 이동을 숨은 퇴행율의 별도 하위 항목(퇴행-기권)으로 정의.
- §3.2.1 기권 분리 블록: "환경 간 기권율 차이를 AIR과 나란히 의무 보고한다(기권 유도로 AIR을 낮추는 경로 차단)" 1문장 추가. Reflection 환경(⑤)에서 특히 점검함을 명시.

### P1-2. 기여 서사 재배치 (W3)

- §1.1 기여 목록 순서 변경: **완화 회계(현 기여 2)를 기여 1로**, 프레임워크(현 기여 1)는 "이를 가능하게 하는 도구"로 종속 배치.
- 한 줄 요약도 같은 구조로 재작성: "완화 기법의 EM 이득이 진짜 추론에서 오는지 회계 감사한다. 이를 위해 3단계 전환 행렬을 정립한다" 순서.
- 제목 후보 재검토(선택): "Lost in Translation" 관용구 의존 축소. 회계 프레임을 담은 부제 검토 (예: *Auditing Where Accuracy Gains Come From under RAG Conflicts*).
- §2.3.1 Li et al. 차별화 문단에 "현상 보고 vs 회계·인과"의 대비를 한 단계 강화.

### P1-3. 레짐 통제 실행 가능성 표 (W6)

- **조사:** Qwen3.6-27B thinking 토글 지원 여부, Olmo-3.1-32B-Think의 instruct 형제 존재 여부, gpt-oss reasoning effort 최저 레벨의 실제 거동(사고 길이 0인가) 확인.
- §3.3.3(b)에 모델별 실행 가능성 표 신설: {진짜 토글 / instruct 형제 / effort 근사 / 불가} 중 어디인지 명시.
- gpt-oss의 effort 근사는 "사고 끔이 아니라 짧은 사고"임을 명시하고 **보조 증거로 강등**. 귀속 주장의 주력은 진짜 토글이 되는 계열로 한정.

### P1-4. 의견 트랙 hedge 라벨 (W7)

- §3.2 이중 트랙(자기일관성 182건 트랙)의 답변 입장 라벨을 {트레이스 입장 유지 / 입장 뒤집음 / **균형 병기(hedge)**} 3분류로 확장.
- 판정 규칙 명시: 트레이스가 한쪽으로 기울고 답변이 양쪽을 병기하면 "불일치"가 아니라 "hedge"로 별도 집계 (의견 질의에서 병기는 정당한 행동일 수 있음).
- hedge 비율 자체를 부가 관측으로 보고 (충돌 유형별 hedge 경향은 그 자체로 흥미로운 신호).

## P2. 실행 리스크

### P2-1. 자원 계획·트리아지 (W8)

- 계획서 말미(§3.3 또는 부록)에 컴퓨트 추정 표 신설: 셀 수(모델×환경×데이터셋×시드) × 문항 × 평균 생성 길이 → GPU-시간 추정. 개입 실험(truncation 다지점 × resampling K회)은 별도 산정.
- **축소 우선순위(트리아지) 사전 선언:** 자원 부족 시 떨어뜨리는 순서 = ③보강(부록 B 상관 분석, 유형 인지) → 환경 축소(⑤→③개) → 시드 축소(5→3, 단 CI 병기 유지). 주력(①완화 회계)과 검증(②RQ3·RQ4)은 사수.
- 판정자 API 비용도 산정에 포함 (유료 API 사용 전 비용예측 원칙과 정합).

### P2-2. 자동 매핑 복수 매칭 발동률 사전 점검 (Q2)

- **실험 전 데이터 점검 작업:** 사실 충돌 67건에 자동 매핑을 돌려 "복수 문서 매칭/무매칭 → 제외" 발동률을 실측. 시간 충돌에서 과거 문서도 정답 문자열을 포함하는 사례가 얼마나 되는지 확인.
- 결과를 §3.1.1 전처리에 실측치로 기입 ("67건 중 제외 n건, 최종 채점 가능 m건"). 만약 크게 깎이면 P0-2 증강 트랙의 필요성이 더 강해짐 → 상호 참조.

### P2-3. 다수결 경로 안정성 (Q4)

- §3.3.2 흐름 지표 정의에 1문장 추가: "문항별 시드 간 경로 일치도(모드 비율)를 함께 보고하고, 다수결이 과반 미달인 문항(예: 2-2-1)은 흐름 분석에서 불안정 플래그로 분리 집계한다."

## 실행 순서 제안

```
1주차: P0-3, P0-4, P1-1, P1-4, P2-3, P3  ← 문서 수정만으로 끝나는 것 일괄 처리
       P2-2 (데이터 점검 스크립트) 병행 시작
2주차: P0-2 (치환 증강 설계·프로토타입) + P1-3 (모델 토글 조사)
       P0-1 (검정력 표 — P2-2 실측치와 파일럿 수치 확보 후 작성)
3주차: P1-2 (서사 재배치 — 구조 변경이므로 다른 수정 안정화 후 마지막에)
       P2-1 (자원 계획 — 최종 실험 그리드 확정 후)
```

서사 재배치(P1-2)를 마지막에 두는 이유: 기여 순서와 요약을 바꾸면 본문 전반의 참조·강조가 연쇄적으로 움직이므로, 국소 수정이 모두 끝난 뒤 한 번에 하는 편이 안전하다.
