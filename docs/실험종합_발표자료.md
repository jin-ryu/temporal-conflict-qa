# RAG 인용의 시점 정확성 평가 — 실험 종합 (발표/슬라이드용)

작성: 2026-06-29 · exp03(통제) + exp04(현실) 종합

> **한 줄 메시지**: AI가 검색해서 답할 때, 검색결과에 모순되는 정보가 섞이면 — **AI가 *틀린 답*을 해도, 표준 인용평가(CitePrec)는 81~100% 확률로 "근거 잘 댔다"고 통과시킨다.** 사용자는 인용을 보고 *틀린 답을 신뢰*하게 된다. 인용 평가에 *"답이 맞았나"는 잣대*가 빠져 있다. (시간 충돌이 이를 *깨끗하게 측정 가능한* 대표 무대.)

## 2. 원본 데이터셋 가공 방법

### 실험 A (HoH) — 위키 편집이력을 사람이 검수해 만듦 (AI 생성 없음)

HoH 원본은 위키 한 문서가 시간에 따라 어떻게 바뀌었는지를 담은 데이터다. 이를 4단계로 가공했다.

1. **청크화** — 위키 원문을 문장 5개씩(3문장 겹침) 잘라 검색 단위 조각으로 만든다. 실제 RAG가 검색해 오는 모습을 재현하기 위함이다.
   - 한 묶음의 구성: *옛 버전 조각 1개 + 새 버전 조각들 + 관련 없는 조각(함정)*, 최대 10개.
2. **기계 정제** (599→152건) — 자동으로 걸러낼 수 있는 불량 항목을 제거한다.
   - 답↔근거 불일치: 정답의 핵심 단어가 근거 문서에 아예 없는 것.
   - 채점이 애매한 답: 5단어 초과, 측정단위 포함(kg·lbs), 숫자 위주(연도·체중, 예 "440 lbs").
   - 편집 다툼: 한 사실이 한 번에 여러 값으로 바뀐 것 / 옛·새 답이 사실상 같은 것(정식명↔약칭).
3. **사람 검수** (핵심, 152→219건) — *시간이 지나며 진짜로 바뀌는 사실*만 사람이 직접 골라낸다.
   - 채택: 현직자(시장·장관·코치), 선수 소속팀, 회사 소유주, 챔피언, 기관·경기장 개명, 승강, 선거.
   - 제외: 고대사·출생지·국적처럼 *시간과 무관한 고정 사실*, 학명 재분류, 단순 집계 오류.
   - 판단 기준: *"옛 답이 그 옛 시점엔 진짜로 맞았나?"* — "그 시점의 정답"이 성립하는 것만 남긴다.
4. **질문에 시점 명시** — 원래 질문 앞에 "As of 2024-09, …"를 붙여 어느 시점을 묻는지 정한다. AI가 만든 게 아니라 정해진 양식이다.

> 역할: 실험 A는 시점을 명시한 *통제* 질문(과거 180 + 현재 대조 39). 시점을 안 정한 완전 현재지향은 실험 B가 담당한다 — A의 원본 질문을 시점 없이 쓰면 정답이 모호해 채점이 깨끗하지 않기 때문.

### 실험 B (rag_conflicts) — 실제 웹 검색결과를 손대지 않고 그대로 사용

rag_conflicts는 Google이 실제 질문을 검색해 모은 결과에 충돌 유형 라벨을 붙인 데이터다. 질문도 문서도 바꾸지 않고 그대로 썼다.

1. **유형 선택** — 전체 458건 중 *"오래된 정보로 인한 충돌"* 유형 62건만 고른다.
2. **형식 변환** (변형 없음) — 검색결과를 문서 조각으로, 원래 질문을 그대로 질문으로, Google이 제공한 correct_answer(최신값)를 정답으로 삼는다.
3. **충돌 필터** (코드 자동, 사람 검수 아님) — 변환 스크립트가 규칙으로 검사해, *정답(최신)을 담은 문서*와 *옛 문서*가 둘 다 있어 충돌이 성립하는 **51건**만 자동 채택한다. (정답 담은 문서가 있나·옛 문서가 있나·날짜가 갈리나를 텍스트 매칭으로 판정.)
   - 탈락한 11건의 사유: 정답을 담은 문서가 없음 6건, 문서 날짜가 안 갈림(시점 구분 불가) 3건, 옛 문서가 없음(충돌 자체가 없음) 2건.
   - → 즉 *"옛/새가 실제로 공존하는 진짜 충돌"* 이 아닌 항목을 거른 것. 충돌이 없으면 틀린 인용(★)을 측정할 수 없기 때문.
   - 검색 노이즈(봇 차단·에러 페이지 등)는 *제거하지 않고* 현실 그대로 둔다. 실제 RAG가 마주하는 환경이기 때문이다.

## 3. 데이터셋 예시 (실제 JSON 구조)

각 문항은 아래 JSON 형식. `chunks`의 `label`: `outdated`(옛)/`current`(새·정답)/`distractor`(함정), `last_modified_time`(문서 시점), `evidence_chunk_id`(시점-유효 정답 문서).

### 실험 A 예시 — "LA 시의회 President pro Tempore" (충돌 219건 중 1건)
```json
{
  "id": "hoh_74_outdated_0",
  "new_question": "As of September 2024, who is the current President pro Tempore
                   of the Los Angeles City Council?",
  "target_answer": "Marqueece Harris-Dawson",          // 9월 시점 정답 ✓
  "evidence_chunk_id": 23,                              // 이 문서를 인용해야 맞음
  "chunks": [
    {"chunk_id": 23, "label": "outdated",  "last_modified_time": "2024-09-01",
     "text": "...President pro Tempore is Marqueece Harris-Dawson..."},   // 옛(정답)
    {"chunk_id": 1,  "label": "current",   "last_modified_time": "2024-10-01",
     "text": "...President pro Tempore is Bob Blumenfield..."},          // 새(오답 유발)
    {"chunk_id": 2,  "label": "distractor","last_modified_time": "2024-10-01",
     "text": "As a nonpartisan council, the City Council does not..."}   // 함정
    // ... 총 10개
  ]
}
```
*(번역)* "2024년 9월 기준 LA 시의회 President pro Tempore는?" → **정답 Marqueece Harris-Dawson**(9월 문서). AI가 새 문서(Bob Blumenfield)로 끌리면 → 시점 틀린 인용 ★.
- 전체: **충돌 219건**, 각각 옛 답↔새 답 명확히 다름, 문서 평균 10개.

### 실험 B 예시 — "FBI 국장" (충돌 51건 중 1건)
```json
{
  "id": "rc_2_current",
  "new_question": "who is the director of the fbi",     // 시점 안 정한 자연 질문
  "target_answer": "Kash Patel",                        // 최신 정답 ✓
  "chunks": [
    {"chunk_id": 0, "label": "outdated",    "last_modified_time": "2016-05-03",
     "text": "Directors, Then and Now ..."},                // 옛 명단
    {"chunk_id": 1, "label": "current_dup", "last_modified_time": "2016-06-13",
     "text": "The current Director is Kash Patel ..."},      // 정답 담았으나 옛 시점
    {"chunk_id": 2, "label": "current",     "last_modified_time": "2025-03-11",
     "text": "Director Kash Patel ... (BBC 2025)"}           // 최신·정답
    // ... 총 9개 (2016~2025 뒤섞임, CAPTCHA 에러 페이지 등 노이즈 포함)
  ]
}
```
*(번역)* "FBI 국장은?" → **정답 Kash Patel**(최신). AI가 옛 국장 담긴 문서에 속으면 → 시점 틀린 인용 ★.
- 전체: **충돌 51건**, 2~10년 시차 문서 뒤섞인 실제 웹, 문서 평균 9개.

### 3-1. 두 데이터셋이 의미하는 바

| | 실험 A (HoH) | 실험 B (rag_conflicts) |
|---|---|---|
| **충돌 종류** | 시간 | 시간 |
| **질문 방향** | 과거 시점 묻기 | 현재 묻기 |
| **AI의 실패 방향** | 과거 물음 → *최신*에 끌림 | 현재 물음 → *옛것*에 속음 |
| **난이도** | 통제됨 (깨끗) | 자연스러움 (노이즈) |
| **역할** | **통제된 증명** (internal validity) | **현실 검증** (ecological validity) |

→ **두 실험이 상보적**: 실험실(A)에서 깨끗하게 증명, 야생(B)에서도 동일하게 일어남을 확인. **충돌은 *양방향*(과거↔현재) 모두 AI를 실패시키고, 통제·현실 양쪽에서 재현된다.**

> 참고: 실험 A에는 "과거 시점 질문" 180건 외에, **"현재 시점 질문" 39건도 대조군**으로 포함. → 과거 질문은 30% 틀리는데 현재 질문은 10%만 틀림 = *실패가 특히 "과거를 물을 때" 심함*을 보여줌.

### 4-0. 실험 규모 요약

| 분석 | mis-attr, faithfulness, 위치 ablation, 지표 일반성 | mis-attr, faithfulness |

### 4-1. AI에게 무엇을 어떻게 넘기는가 (프롬프트)

데이터의 *모든 정보*를 주는 게 아니다. **질문 + 문서 조각들(번호·타임스탬프·본문)만** 넘기고, 정답·정답청크 라벨은 *채점에만 쓰고 모델엔 주지 않는다.* (모델은 청크를 보고 *추론으로* 답해야 함.)

**모델에 *넘기는* 것 / *안 넘기는* 것:**

| 데이터 필드 | 모델에 넘김? | 비고 |
|---|---|---|
| 질문 (`new_question`) | ✅ | |
| 문서 번호 + 본문 (`chunks[].text`) | ✅ | 충돌·정답·함정 다 섞어서, *순서 무작위* |
| 문서 타임스탬프 (`last_modified_time`) | ✅ | `[modified: ...]` 로 표기 |
| 정답 (`target_answer`) | ❌ | *채점에만* 사용 |
| 정답청크 라벨 (`evidence_chunk_id`, `label`) | ❌ | *채점에만* 사용 |

**위치 편향 통제 — 청크 순서 무작위 셔플:**
> RAG 컨텍스트에 청크를 넣을 때 **매 문항 문서 순서를 무작위로 섞는다**(seed 고정·재현 가능). 정답·충돌·함정 문서가 *항상 특정 위치*(예: 최신이 맨 위/맨 아래)에 오지 않게 함. → 모델이 *내용/시점*이 아니라 *위치*로 문서를 고르는 혼입(confound)을 차단. (별도로 §5-4 위치 ablation에서 위치 효과를 직접 측정해 분리.)

**시스템 지시** (모든 실험 공통):
> "문서들에는 각각 번호와 *수정 날짜(타임스탬프)* 가 붙어 있다. **날짜를 보고 질문이 가리키는 시점에 유효한 문서를 골라** 그 문서를 근거로 답하라. 인용은 [번호]로 표시. `<reasoning> 간단 추론 </reasoning> <answer> 짧은 답 [번호] </answer>` 형식으로만 출력."

**실험 A — 사용자 메시지 실제 예시:**
```
[Query] As of September 2024, who is the current President pro Tempore of the LA City Council?

[Document 1] [modified: 2024-10-01]
...The current President pro Tempore is Bob Blumenfield...         ← 새(오답 유발)
[Document 2] [modified: 2024-09-01]
...The current President pro Tempore is Marqueece Harris-Dawson... ← 옛(정답)
[Document 3] [modified: 2024-10-01]
As a nonpartisan council, the City Council does not...            ← 함정
... (총 10개, 무작위 순서)
```
→ 모델은 *"9월 질문이니 9월 문서(2)를 골라야"* 를 **타임스탬프 보고 추론**해야 함. (정답·라벨은 안 줌.)

**실험 B (rag_conflicts)** — 같은 형식. 단 타임스탬프가 *실제 웹 수집일*(2016~2025 등)이고, 노이즈 문서(CAPTCHA 등)도 그대로 포함.

- **인용을 [번호]로 다는 방식 = ALCE(표준 RAG 인용평가)와 동일.**
- A·B 모두 시점 단서(타임스탬프)와 지시를 *모두 주는* 관대한 조건 → 그래도 틀리면 진짜 실패.
- 채점은 **무료 결정론적 방법**(유료 LLM 심판 없음) → 누구나 재현 가능.

### 4-2. 평가 지표 — 기존의 함정과 우리 지표 (수식)

**① 정답 채점 — EM**

$$\text{EM} = \mathbb{1}\big[\ \hat{a} = a^{*}\ \big]$$

- $\hat{a}$ = AI 답, $a^{*}$ = 정답. "답이 맞았나" (의미매칭).

**② 기존 표준 인용 지표 — CitePrec (ALCE)**

$$\text{CitePrec} = \mathbb{1}\big[\ \exists\, c \in S : c \models \hat{a}\ \big]$$

- $S$ = AI가 인용한 문서들, $c \models \hat{a}$ = "문서 $c$가 *AI 답* $\hat{a}$를 뒷받침".
- 즉 **"인용한 문서가 *내 답*을 받쳐주나?"**
- ⚠️ **결정적 함정 (순환성)**: 앵커가 *AI 자신의 답* $\hat{a}$ → **AI가 *틀린 답*을 내고 *그 틀린 답을 담은 문서*를 인용하면 자동으로 통과.**

$$\boxed{\ \text{EM}=0 \ \wedge\ \text{CitePrec}=1\ \text{ 가능}\ }$$

> *틀린 답인데, 표준 인용평가는 "근거 잘 댔다"고 통과* → 사용자가 *틀린 답을 인용 보고 신뢰.*

**③ 우리 헤드라인 지표 — mis-attribution (★)**

$$\bigstar = \{\ \text{EM}=0 \ \wedge\ \text{CitePrec}=1\ \}, \qquad
\text{mis-attr} = P(\text{CitePrec}=1 \mid \text{EM}=0)$$

- **★** = "답은 틀렸는데 표준 인용평가는 통과시킨 칸" = *우리가 찾는 사각지대.*
- **mis-attr** = *틀린 답 중* 표준 인용평가가 놓친 비율 (높을수록 인용평가가 눈멈).
- → *"시점" 개념 없이* 누구나 이해 + EM(정답)을 *재료로* 써서 중복 없음. **정답·인용 내용만 필요**(정답청크 라벨 불필요) → 충돌 종류와 무관하게 적용 가능한 일반 지표.

**EM × CitePrec 2×2 — 우리 지표가 보는 칸:**

```
                  CitePrec = 1               CitePrec = 0
              (인용평가 "통과")           (인용평가 "실패")
          ┌──────────────────────────┬──────────────────────────┐
  EM = 1  │   ✅ 제대로                │   답 맞고 인용만 빗나감     │
 (답 맞음) │   정답 + 좋은 인용         │   (드묾)                  │
          ├──────────────────────────┼──────────────────────────┤
  EM = 0  │   ★ mis-attribution      │   정직한 오류              │
 (답 틀림) │   틀린 답인데 인용은 통과   │   틀린 답 + 인용도 빗나감   │
          │   ← 기존 평가가 *못 잡음*   │   ← 기존 평가가 *잡음*      │
          └──────────────────────────┴──────────────────────────┘

   mis-attribution = ★ / (틀린 답 전체) = EM0·CP1 / (EM0·CP1 + EM0·CP0)
```

> **실제(GPT-5.5, 실험 A as-of-past)**: 틀린 답 35건이 **전부 ★ 칸**(EM0·CP1=35, EM0·CP0=0) → mis-attr **100%**. 즉 GPT가 틀린 답을 한 35번 *모두* 표준 인용평가는 "근거 잘 댔다"고 통과시킴. 정직한 오류(인용도 빗나감) 칸은 0건.

**④ faithfulness 분류 — 틀린 인용이 *진짜* 사용인가**

문서제거 counterfactual: 틀린 답이 *단일조건(옛만/새만)* 답과 일치하면 그 문서에 *행동 의존* = **faithful-wrong**(진짜 보고 틀림), 아니면 **post-rat**(사후 인용).

> 기존 평가축 비교: **correctness**(ALCE, 답 받치나) · **faithfulness**(Wallat 2025, 진짜 썼나) — 둘 다 *"틀린 답×좋은 인용"* 의 괴리를 직접 측정 안 함. (보조 지표) TV_cite = 인용이 *시점-유효 문서*인가(시간 충돌 특화) — mis-attr의 시간 버전.

### 4-3. 추가 분석 방법 4가지

**(가) main 실험** — mis-attribution 측정. "틀린 답에 인용평가가 통과하나?" (5모델 × 2데이터셋)

**(나) faithfulness 분류** — *문서를 빼보는 반사실(counterfactual)* (AI 재호출 없이 기존 응답으로 계산):
- 틀린 답을 했을 때, *그 충돌 문서를 빼면 답이 바뀌나?*
  - **바뀜 → faithful-wrong** (그 문서를 *진짜 보고* 답함) ← 우리 신규 범주
  - **안 바뀜 → post-rationalization** (답은 이미 알고 인용만 갖다붙임) ← Wallat 2025 범주
- 각 항목의 *옛 문서만 / 새 문서만* 조건이 이미 있어 무료로 비교.

**(다) 인용 편향 분석** — *틀릴 때 어느 문서를 인용하나* 4분류(충돌·정답·distractor·무인용):
- "실패가 랜덤인가, 방향성이 있나?"를 검증. 청크 순서는 셔플(위치 통제).
- 충돌 문서로 쏠리면 → 그 문서가 틀린 답을 받쳐 ★ 발생 → mis-attribution의 *원인*을 규명.

**(라) 위치 ablation** — *정답 문서를 프롬프트 맨앞/맨뒤에 강제 배치*해 재측정 (exp03):
- "AI가 내용이 아니라 *위치(맨 뒤 문서)* 로 고르는 건 아닌가?"를 검증.

## 5. 실험 결과

### 5-1. main — 기존 인용평가는 "틀린 답"을 못 잡는다 (mis-attribution)

모델별 EM × CitePrec 2×2 네 칸 (§4-2 박스 구조 그대로). **★ = EM=0·CP=1 = 틀린 답인데 인용평가 통과** = 사각지대.

**실험 A (HoH, 통제·시간, as-of-past n=180):**

| 모델 | EM1·CP1 (정상) | EM1·CP0 | **★ EM0·CP1** | EM0·CP0 (정직오류) | **mis-attr** |
|---|---|---|---|---|---|
| GPT-5.5 | 145 | 0 | **35** | 0 | **100%** |
| Gemini 3.1 | 121 | 0 | **54** | 5 | **92%** |
| Mistral-24B | 119 | 0 | **56** | 5 | **92%** |
| Qwen3-32B | 90 | 0 | **89** | 1 | **99%** |
| Qwen3-8B | 72 | 0 | **105** | 3 | **97%** |

**실험 B (rag_conflicts, 현실·시간, n=51):**

| 모델 | EM1·CP1 (정상) | EM1·CP0 | **★ EM0·CP1** | EM0·CP0 (정직오류) | **mis-attr** |
|---|---|---|---|---|---|
| GPT-5.5 | 27 | 0 | **20** | 4 | **83%** |
| Gemini 3.1 | 33 | 4 | **13** | 1 | **93%** |
| Mistral-24B | 27 | 3 | **17** | 4 | **81%** |
| Qwen3-32B | 26 | 2 | **20** | 3 | **87%** |
| Qwen3-8B | 28 | 1 | **20** | 2 | **91%** |

**읽는 법:**
- **★ 칸이 틀린 답의 대부분** → mis-attr 81~100%: 틀린 답을 기존 인용평가가 "정상 인용"으로 통과.
- **정직오류(EM0·CP0) 칸은 거의 비어 있음** (0~5건) → 틀려도 인용은 "통과"로 잡힘 = 평가가 못 거름.
- **EM1·CP0(맞는데 인용 빗나감)도 거의 0** → 맞을 땐 인용도 정확 → ★는 *틀림에 특정된* 현상.
- **최강 GPT조차** 실험 A서 틀린 답 35건 *전부* ★ (mis-attr 100%). (CiteRecall·AIS 등 다른 표준 지표도 동일하게 눈멈.)

### 5-2. faithfulness 분류 — "진짜 보고 틀렸다" (Wallat과 구별)

틀린 인용 중 *faithful-wrong*(충돌 문서를 진짜 사용해 틀림) 비율:

| | A (통제) | B (현실) |
|---|---|---|
| faithful-wrong | **63~81%** | **43~57%** |

- → 두 실험 모두 **상당수가 "문서를 진짜 보고 따라가서" 틀림** (대충 갖다붙인 post-rat 아님).
- → Wallat 2025의 post-rationalization과 **구별되는 새 실패 유형**, 통제·현실 양쪽서 재현.

### 5-3. 인용 편향 — 틀릴 때 *무엇을* 인용하나 (★의 메커니즘)

틀린 답일 때 모델이 인용한 문서를 4분류. **청크 순서는 매 문항 무작위 셔플**(위치 통제) → 편향은 위치 아닌 *내용/시점*에서 옴.

**실험 A (HoH 과거 질문, 정답=옛 문서) — 틀릴 때 인용 대상:**

| 모델 | 틀린답 | **충돌(최신측)** | 정답문서 | distractor |
|---|---|---|---|---|
| GPT-5.5 | 35 | **77%** | 9% | 14% |
| Gemini | 59 | **80%** | 7% | 8% |
| Mistral-24B | 61 | **67%** | 23% | 10% |
| Qwen3-32B | 90 | **81%** | 6% | 13% |
| Qwen3-8B | 108 | **74%** | 10% | 15% |

**실험 B (rag_conflicts 현실 웹, 정답=최신) — 틀릴 때 인용 대상:**

| 모델 | 틀린답 | **충돌(옛것)** | 정답문서 | 무인용 |
|---|---|---|---|---|
| GPT-5.5 | 24 | **46%** | 21% | 33% |
| Gemini | 14 | **71%** | 14% | 14% |
| Mistral-24B | 21 | **67%** | 29% | 5% |
| Qwen3-32B | 23 | **57%** | 35% | 9% |
| Qwen3-8B | 22 | **64%** | 18% | 18% |

*(B는 현실 웹이라 distractor 라벨 없음 — 충돌 문서는 "옛 시점" 문서. 무인용 비율이 A보다 높은 건 노이즈 문서(CAPTCHA 등) 때문.)*

- **A·B 모두 틀리면 *충돌 문서*로 강하게 쏠림** (A 67~81%, B 46~71%). 엉뚱한 문서(distractor)는 A서 8~15%로 소수 → 실패는 *랜덤 아니라 방향성 있는 편향*.
- **현재 질문(정답=최신)에선 방향이 뒤집힘**: 틀리면 *옛 문서*로 쏠림(58~82%) → "최신 맹목 선호"가 아니라 *질문이 가리킨 시점의 반대로 끌림* = recency-pull의 대칭.
- **이것이 ★(mis-attribution)의 메커니즘**: 틀린 답일 때 충돌(틀린시점) 문서를 인용 → 그 문서가 *틀린 답을 받쳐줌* → CitePrec 통과 → ★. 즉 "어디로 끌리나"가 "★냐 정직한 오류냐"를 결정.

### 5-4. 위치 ablation — 메커니즘은 "위치 편향 + 시점 추론 실패"의 혼합

정답 문서를 맨앞 vs 맨뒤에 둘 때 시점 정확 인용율 변화 (Δ):

| 모델 | 맨앞 | 맨뒤 | Δ |
|---|---|---|---|
| Mistral-24B | 0.43 | 0.84 | **−0.41** (위치 영향 큼) |
| Qwen3-32B | 0.55 | 0.73 | −0.18 (중간) |
| Qwen3-8B | 0.56 | 0.63 | −0.07 (거의 없음) |

- → AI는 *맨 뒤 문서를 선호*하는 위치 편향이 있으나 **모델마다 다름.**
- → 충돌 실패는 *위치만으로 설명 안 됨* (Qwen은 위치 영향 −18%인데 실패는 더 큼) = **위치 편향 + 진짜 시점추론 실패의 혼합.**

## 6. 해석 — 기존 지표가 못 찾은 문제를 찾음

### 우리가 찾은 것 = "인용 평가의 맹점 (mis-attribution ★)"
- **표준 인용평가(ALCE의 CitePrec)는 *AI 답*을 앵커로 삼아 순환한다** → AI가 틀린 답을 내고 그 답을 담은 문서를 인용하면 통과.
- 따라서 *틀린 답이어도* "인용 잘함" 정상 판정 → **사용자도, 평가지표도 속는다.**
- 우리 헤드라인 지표 **mis-attribution**(틀린 답 중 CitePrec 통과 비율)이 이 빠진 잣대를 드러냄.

### 핵심 발견 5가지
1. **mis-attribution은 보편적**: 5모델·2데이터셋 모두 81~100%. **최강 GPT조차** 틀린 답을 거의 다 "잘 인용"으로 통과.
2. **인용 편향에 방향성**: 틀릴 때 *충돌(최신측) 문서*로 67~81% 쏠림(distractor는 8~15% 소수) → 실패는 랜덤 아닌 *recency-pull*. 이게 ★의 직접 메커니즘.
3. **양방향 실패** (최신 편향의 대칭): 과거 질문 → *최신*에 끌림 / 현재 질문 → *옛것*에 속음 → 둘 다 기존 지표가 비가시.
4. **faithful-wrong**(우리 고유): 틀린 인용의 43~81%가 *진짜 그 문서를 보고* 틀림 → Wallat 2025의 post-rationalization과 구별, 통제·현실 양쪽서 재현.
5. **통제 + 현실 모두 입증**: 실험실(A)·실제 웹(B) 양쪽 → 인위적 현상 아님.

### 학술적 위치 — 인용평가의 빠진 연결고리

| 평가 축 | 묻는 질문 | 선행연구 |
|---|---|---|
| correctness (인용) | 인용이 *AI 답*을 뒷받침하나 | ALCE (2023) |
| faithfulness | 인용을 *진짜 썼나* | Wallat (2025) |
| **★ mis-attribution** | 인용평가가 *틀린 답*도 통과시키나 (답정확성×인용 연계) | **본 연구 (빈칸)** |

- 가장 가까운 Verified Misguidance(2025)도 *"answer-correctness link는 future work"* 로 명시 → 우리가 그 빈칸을 메움.
- 우리 실패는 *correct(답 받침)·faithful(진짜 사용)인데 답이 틀림* → 기존 축으로 설명 안 됨. **시간 충돌이 이를 *깨끗하게 측정 가능한* 대표 무대**(타임스탬프라는 in-context 판단규칙 덕에 "풀 수 있었는데 틀렸다"가 성립).

### 실제 임팩트 (왜 중요한가)
- **법률**: 소급적용 금지 — 사건 시점의 법령을 인용해야 (틀린 버전 = 법적 오류).
- **금융/감사**: 특정 시점 기준 정확성이 규제 의무.
- **의료**: 옛 지침을 현행처럼 인용 = 환자 위해.
→ 고위험 도메인에서 *틀린 버전 인용*을 현 평가가 못 걸러냄.
