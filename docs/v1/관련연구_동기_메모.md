## 0. 우리가 문제화하는 것 — "인용평가의 시점 맹점(★)"

> **AI가 단 인용이 *답을 뒷받침하는지*는 채점하면서, 그 인용이 *질문 시점에 맞는 문서인지*는 어떤 표준 지표도 안 본다.**

- RAG는 신뢰성 위해 인용을 단다. 표준 채점 = **CitePrec(ALCE)**: "인용 문서가 답을 뒷받침하나?" (시점 무관).
- **맹점(★)**: 옛/새 충돌에서 모델이 *최신(틀린시점)* 문서를 인용해도, 그 문서가 (틀린) 답을 뒷받침하므로 **CitePrec 통과**. 실제론 시점이 틀린 잘못된 인용.
- **증명**: 5모델, 틀린시점 인용의 **91~100%가 CitePrec/CiteRecall/AIS 전부 통과**(지표 불문). 그중 **64~81%는 faithful**(진짜 그 문서 사용) = post-rationalization도 아닌 *새 범주*.
- **함의**: 인용 신뢰성 평가에 *시간 차원*이 통째로 빠져 있다. 법률·금융선 *틀린 버전 인용* = 치명적인데 현 평가가 못 걸름.

## 1. 동기 — as-of-past / 시점정확성이 마이너가 아닌 근거

### 1a. 법률 (가장 강력 — 시점정확성이 *법적 의무*)
- **"Can LLMs Time Travel? Enhancing Temporal Consistency in Legal Agentic Search"** (arXiv 2605.25920, 2025): *"적용법은 사건의 시점과 맞아야 하며, 소급적용(retroactive application)은 법 원칙 위반"*. 중국 형법/형소법 개정판별 충돌. LegalSearch-R1(RL)로 시간일관성 강제. → **우리 as-of-past 주장과 정확히 일치.**
- **Stanford RegLab Legal RAG Benchmark — Housing Statute QA** (reglab.github.io/legal-rag-benchmarks): *"같은 법 질문이 *법령 버전*에 따라 정반대 답"*. 50+ 미국 주 주거/퇴거법, Yes/No + 근거 법령. → **우리 충돌 구조와 동일, 공개 데이터(잠재 실험셋).**

### 1b. 금융 (point-in-time = 규제 필수)
- **FinTMMBench** (arXiv 2503.05185, 2025): 최초 temporal-aware 멀티모달 금융 RAG 벤치, *모든 질문이 temporal*. tabular/text/time-series/visual.
- **ECT-QA**: earnings-call 기반 temporal QA (fact + trend).
- point-in-time 재무데이터·bitemporal = 감사/규제 의무.

### 1c. DB/산업 표준 (as-of는 표준 프리미티브)
- **SQL:2011 system-versioned temporal tables** — `FOR SYSTEM_TIME AS OF <date>`. MS SQL 등 주요 DBMS 지원. 감사·포렌식·복구에 사용 = as-of 질의는 *산업 표준*.
- bitemporal (valid-time vs transaction-time): 금융·규제 컴플라이언스 핵심.

### 1d. 멀티도메인 temporal 벤치 (최신·경쟁지형)
- **TEMPO** (arXiv 2601.09523, 2026.1): 최초 temporal reasoning + reasoning-intensive retrieval, 13도메인(법률·금융 포함), 1730 쿼리. 최고모델도 NDCG@10 32.0 = 어려움.
- **TimE / TempRetriever / FinDER** 등.

## 2. 메커니즘 근거 — recency bias (우리 위치 ablation과 연결)

- **"Do Large Language Models Favor Recent Content? A Study on Recency Bias in LLM-Based Reranking"** (arXiv 2509.11353, **SIGIR-AP 2025**): LLM 리랭킹의 recency 편향 직접 연구, 최신 vs 관련성 긴장, 선호 최대 25% 역전.
- **원인 규명** (검색 종합): pretraining에서 *최근 토큰이 가장 informative* → 최근 attend 편향 학습 + **RoPE positional embedding**이 먼 거리 attention 감소 유도 → 최근 토큰 선호. → **우리 위치 ablation(evidence 맨뒤=잘 고름)의 *메커니즘적 설명*.**
- "Attention Sorting Combats Recency Bias" (2310.01427): 완화 시도.

## 3. 선행연구 대비 우리 차별점 (related work용)

| 연구 | 무엇 | 우리와 차이 |
|---|---|---|
| **ALCE** (Gao 2023, EMNLP) | CitePrec/recall — 인용이 답 뒷받침하나 | *시점 무관* = 우리 foil(맹점 대상) |
| **Wallat 2025** (ICTIR) | citation faithfulness, post-rationalization 57% | 인용이 *진짜 사용*됐나. 우리=*사용됐는데 시점 틀림*(별도 범주) |
| **HoH** (ACL 2025) | outdated 정보가 답 정확도 떨어뜨림 | *답*만, *인용평가 맹점* 미다룸 |
| **Can LLMs Time Travel** (2025) | 법률 시간일관성, RL 해결 | *검색/생성 해결*, 인용평가 맹점 아님 |
| **Do LLMs Favor Recent** (SIGIR 2025) | 리랭킹 recency 편향 | *리랭킹* 행동, 인용평가 맹점 아님 |
| 시간-RAG(TimeR4·T-GRAG·FinTMMBench) | temporal 검색/해결법 | *해결법*(레드오션), 우리=측정/진단 |

→ **빈칸 = "충돌 시 인용평가(attribution)가 시점오류를 못 잡는다(★) + faithful-but-wrong-time이라는 범주"** — 아무도 안 함.

## 4. 프레이밍 (순위) — niche 비판 회피

1. **knowledge conflict 하 citation faithfulness 평가의 시점 맹점(★)** ← 헤드라인 (큰 영역 + 우리 고유)
2. **recency-over-relevance bias** (모델이 관련성보다 최신 신뢰) ← 메커니즘 동기
3. inter-context conflict resolution
4. as-of-past QA = *위를 드러내는 통제된 probe* (주제 아님, 도구)

**동기 한 문단(초안)**: *"과거 시점 기준 정확성은 법률(소급적용 금지[Time Travel])·금융(point-in-time 규제[FinTMMBench])·감사(SQL:2011 AS OF)에서 필수다. 이는 모델의 recency 편향[SIGIR2025]과 인용 신뢰성[Wallat] 문제의 구체적 발현이다. 그러나 표준 인용평가(ALCE)는 인용의 시점 유효성을 측정하지 않는다. 우리는 통제된 벤치마크로 이 맹점(★)을 측정한다."*
